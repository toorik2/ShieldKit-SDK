Bitcoin Cash · fixed 0.1 BCH notes · Chipnet-first

Private notes. Public rules. Your pool.

ShieldKit is a toolkit to birth and run your own shielded pool on BCH: deposit 0.1 BCH notes, transfer them without linking owners on-chain, withdraw to transparent scripts. Proofs stay local; the chain only verifies. This site explains the system clearly — the notes stay private.

Unaudited WIP. Teaching page for the current profile — not an audit report, not a mainnet product claim. Prefer Chipnet until SECURITY and red-team docs say otherwise.

Denomination

0.1 BCH

Every note is exactly 10M sats. No arbitrary amounts.

Default capacity

16 live

Max reserve 1.6 BCH if full. Live count = unspent notes (starts at 0).

Miner fee

1 sat/B

Exact equality on every protocol transaction. Forever for this profile.

Framing

What it is · what it is not

It is

A single-asset, fixed-denomination shielded pool on Bitcoin Cash. You hold keys, RPC, and broadcast. State is a State NFT tip plus Merkle trees. Groth16 is checked by covenant unlocks (densFuel pin), not a bridge.

deposit private transfer withdraw your genesis no admin after birth

It is not

Not EVM. Not multi-asset. Not hosted privacy SaaS. Not network anonymity. Not “anonymous” when only one note is live. Not upgradeable after genesis. The Chipnet playground is a different instance than a pool you create.

no sequencer no protocol fee no magic mixer crowd

You run instance + hot fee wallet + RPC. Doctor checks tip, fees, capacity. Deposit needs a fee UTXO ≳ ~10.07M sats (0.1 BCH + PF7/bind/settle pads); transfer/withdraw floors are ~71k sats. Tip is one UTXO — settles serialize. Multi-user wallets each keep their own open-note journal; a shared ops state.json is a lab convenience, not the multi-tenant product model.

You see every settle’s graph, size, fee, roots, nullifiers, boundaries. You do not cryptographically learn which live commitment a nullifier opens — unless N=1 or side channels (timing, unique amounts elsewhere) collapse candidates. Wallet selection order is not a field on the transaction.

On-chain machine

Covenants, not EVM · how state lives and moves

There is no Solidity contract and no admin key. The pool is a CashToken mutable NFT tip locked by profile-derived BCH covenants. Every act spends the tip and recreates it with a new commitment.

Not a “smart contract address”

Scripts are P2SH32 densFuel verifiers + short P2S locks (binding + state trampoline), derived from the authenticated profile. After genesis those locks never change.

Single tip UTXO

Exactly one live State NFT. Concurrent settles race on that outpoint — one spends it; the rest rebuild against the new tip.

Reserve rides the tip

Tip value = 1080 (carrier base) + reserveSats. Live notes always satisfy reserve = live × 10M.

Lifecycle — birth → advance

Step through what the chain actually does. Secrets and open-note journals stay off-chain.

Genesis spends a tokenless category input (vout 0). It mints the sole mutable State NFT under that category, locks it with the profile’s state trampoline, and commits the empty state (live = 0, reserve = 0, empty roots). Fee = wireBytes × 1. maximumReserve / capacity is frozen here forever.
Complete PREP is a public funding tx with exactly 10 outputs: PF7 carriers exec0…exec4, genesis, terminal (indices 0–6), then binding (7), fee (8), and P2PKH change (9). Deposit binding value = 1000 + 10M sats; transfer/withdraw binding = 1000 only. PREP does not move the tip.
SETTLE has exactly 10 inputs in fixed order: 7 densFuel unlocks · binding (unlock = PUSHDATA2 + 752-byte SCAR packet) · previous state tip · transparent fee. Outputs: successor tip (same state lock, post-state NFT commitment, value = 1080 + postReserve) · optional withdraw 0.1 BCH · fee change. Groth16 is enforced by the PF7 unlocks; the packet digests pre/post state + context.
openNotes is a wallet journal (ρ, r, sk, leaf index) — not a chain UTXO list. On-chain you see roots, live count, nullifiers, and ciphertext recovery records. Anyone can recompute the public tip state from history; only secret holders open specific notes.

▸ The verifier — Groth16, BN254, densFuel Collapsed by default · math under the hood

ShieldKit does not run an EVM. A Groth16 proof is built offline; Bitcoin Cash checks it with a split densFuel verifier (PF7) baked into seven P2SH32 unlocks.

One sentence each

Relation

shielded-action-v2 — one circuit for deposit, transfer, and withdraw. Witness holds secrets; public inputs are tiny.

Proof system

Groth16 over BN254 (alt_bn128). Proof is a few group elements; verify is a pairing equation.

On chain

densFuel / PF7 — seven verifier inputs, not one giant script. Unlock sizes stay under BCH limits (~10kB each).

Curves & hashes (field guide)

BN254 (proof curve)

Pairing-friendly curve used by Groth16. Field prime ≈ 254 bits. Snarks live here: proof points, VK, public inputs as field elements.

aka alt_bn128 · same family as many Ethereum snarks

BabyJubJub (wallet curve)

Embedded curve for spend / recovery scalars. SP = [sk]Base8, RP = [rk]Base8. Authority ak Poseidon-binds both points.

Poseidon (in-circuit hash)

SNARK-friendly sponge for note commitments, nullifiers, Merkle nodes, and pool state commitment. Domain-separated tags (note, nullifier, trees, pool state).

SHA-256 (out-of-circuit bridge)

Compresses the full action packet to two public limbs so the circuit stays small while the covenant still sees the full SCAR bytes in the binding unlock.

Trees the relation talks about

Note tree · depth 32

Append-only commitments. Deposit/transfer add a leaf; withdraw does not grow the note tree.

Nullifier tree · depth 128 (sparse)

Spent markers. Key = low 128 bits of canonical Fr encoding of nf. Double-spend = second insert fails.

Prove offline · verify on BCH

Setup honesty. Local / Chipnet profiles are development-only (not multi-party ceremony). Production privacy claims need a ceremony-backed profile and a new genesis. Changing the circuit, VK, or densFuel pin ⇒ new profile — never a hot-swap.

Operate

Hands-on path

# Birth — capacity immutable after this
npm run create-pool -- --out ./my-pool --with-genesis \
  --scan-fund --max-notes 16 --wallets ./wallets.json --broadcast

npm run shieldkit -- doctor --pool ./my-pool

# Grow live set, then spend (prove+unlock often 30–90s)
npm run shieldkit -- deposit  --pool ./my-pool --wallets ./wallets.json --broadcast
npm run shieldkit -- deposit  --pool ./my-pool --wallets ./wallets.json --broadcast
npm run shieldkit -- withdraw --pool ./my-pool --wallets ./wallets.json --broadcast
